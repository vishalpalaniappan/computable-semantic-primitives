Lets consider a bubble sort algorithm. As a quick reminder, a bubble sort algorithm can be generalized as shown below. The initial participant is an unsorted list and I will list the remaining participants after sharing the sorting steps below.

\begin{enumerate}[noitemsep]
    \item Initialize right end to size of list.
    \item Set current position to first element of list. 
    \item Compare current element to adjacent element to its right.
    \item Swap if not in order.
    \item Move onto next pair.
    \item Repeat steps 3,4 and 5 until right end is reached.
    \item Decrease right end by one to indicate sorted items.
    \item Repeat steps 2-7 until entire list is sorted.
\end{enumerate}

So using this, we can establish the design of bubble sort.

We have the following participants:

\begin{enumerate}[noitemsep]
    \item Current Position: Current position being inspected.
    \item Right Position: Sorted elements to right of this position.
    \item Unsorted List: List of numbers to be sorted
\end{enumerate}

\subsubsection{InitializeRightPosition}

\begin{greyquote}
    Store the length of the list in size.\\
    then \\
    Set rightPosition to size.
\end{greyquote}

In this case, there are three primitive transformations and added "then" between the transformations to indicate that they happen in order.

So I first get the length of the list and then I store the result in the size participant. This is a primitive because I can establish it using the built in operator. If I wanted to implement it myself, I can implement the meaning of length by building a design that will count the number of elements.

Next, I set rightPosition to the size of the list. Both of these simply use the assign operator and it is a primitive.Now the meaning of InitializeRightPosition has been constructed from the primitives.

\subsubsection{SetCurrentPositionToStart}
\begin{greyquote}
    Set leftPosition to 0.
\end{greyquote}

The meaning of this behavior is trivial, it simply sets the participant leftPosition to 0.

\subsubsection{CompareValues}

\begin{greyquote}
    Set leftPosition to currentPosition\\
    then\\
    Store result of add 1 and leftPosition in rightPosition\\
    then\\
    Set leftValue to unsortedList value at leftPosition\\
    then\\
    Set rightValue to unsortedList value at rightPosition.\\
    then\\
    Store result of left position greaterThan rightPosition in shouldSwap
\end{greyquote}

In this case, the meaning of the compareValues behavior is built from multiple primitive transformations. First, there is the direct assignment of one value to another participant. Then an add primitive is executed and the result is saved in a participant. Then the value at the left and right position is saved in the relevant participants. Finally a comparison is done to set the value of shouldSwap participant.
