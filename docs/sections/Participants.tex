In this section, I will be talking about the meaning of participants. The primitive participants have attributes that are established, for example, type. However, as part of the design's meaning, participants can have custom attributes. 

For example, the meaning of a book includes its name and contents. So in the narratives, if I say that the book is assigned a name, then there is a specific attribute of the participant that is being updated. So as part of the narratives I can also specify this.

\begin{greyquote}
    A book has a name and it has contents. The name is a string and content is a string. The books name can be accessed and assigned.
\end{greyquote}

I can create ways in which this participant can be interacted with, so when I say, I get the books name, this has unambiguous meaning.

The principle here is that the meaning has to be entirely unambiguous. So the participant has to be fully specified and that meaning has to be realized. So from the perspective of how this meaning is realized, it can be realized as a class with attributes. In the same way that I setup behaviors as methods that are invoked, the participants can be instances of a class that has been consructed from its meaning. The methods assigned to the class are ways in which you can interact with the participant. 

So as part of the narrative construction, I am describing the participants in the narrative, I can specify the necessary information needed to construct the participant. The engine will be able to reason completely, there is meaning assigned to every part of the narrative.
